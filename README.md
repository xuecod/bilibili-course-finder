# Bilibili Course Finder

> 判断一个 B 站视频值不值得看，不该只看播放量。

一个 [WorkBuddy](https://www.workbuddy.cn) / Claude Code 的 Skill：调用 B 站搜索 API，**用分P大纲、弹幕、评论**判断视频内容质量与适用人群，而不只是数播放量。

适用于任意题材——技术网课、美食做法、健身动作、软件测评、游戏攻略、考试复习。

```
你：帮我找个学 pwn 的网课
它：跑一遍 400 条搜索结果 → 筛出 174 条候选 → 对 8 门做深度体检 → 给 3 门带证据的推荐
```

---

## 为什么需要它

播放量和收藏率会被三种东西污染，肉眼看不出来：

**1. 小样本虚高**
一门 2 万播放的新课收藏率 7.07%，看起来碾压 160 万播放、收藏率 3.65% 的经典课。
但前者收藏绝对量只有 1400，后者是 5.8 万。

**2. 标题挂羊头**
标题写「CTF逆向/CTFweb/CTFpwn/CTFmisc」，看着什么都覆盖。
实际 100 集大纲里 **pwn 相关内容是 0 集**。它靠堆关键词拿到了最高相关度。

**3. 数据造假或污染**
弹幕全是「请评论区留言」「请弹幕留言」——不是观众热情，是 UP 在求互动。
弹幕是「兴趣爱好」「能力提升」这种整齐短句——任务式刷的。

而真正有用的信号藏在细节里：

| 看到的 | 意味着 |
|---|---|
| 高赞评论「小白别炒糖色，容易发苦，改加可乐」 | 这是最有价值的一条，比一万个赞实在 |
| 神评「惊了居然是本人」，附作者个人网站 | 教材作者亲自讲，权威度最高 |
| 弹幕「看完了，已经入职美团，明天开始送外卖」 | 观众在玩梗嘲讽，营销包装嫌疑 |
| P39 弹幕问号率 10.1%，其他章节 1% | 这一段是全课最难点 |

---

## 三层信号

```
元数据层  播放 / 收藏率 / 点赞率 / 分P数 / 发布日     →  有多少人认可
结构层    分P标题列表 = 课程大纲                      →  讲得全不全
内容层    弹幕情绪 + 高赞评论 (+ 可选字幕)             →  讲得怎么样、适合谁
```

脚本只输出**客观数据**，主观判断留给模型。
因为「这条弹幕是在刷互动还是在真心夸」，机器分不出来。

## 用法

### 三种模式

| 模式 | 什么时候用 | 最短时长 | 最低播放 | 结构权重 |
|---|---|---|---|---|
| `any`（默认） | 没说清要课还是要单条视频 | 1 分钟 | 100 | 12/100 |
| `course` | "系统学""打基础""找套课" | 8 分钟 | 500 | 30/100 |
| `clip` | "怎么做""技巧""快速了解" | 不设 | 200 | 0/100 |

判断口诀：**要"学一门" → course；要"解决一件事" → clip；拿不准 → any。**

### 命令

```bash
# 一条龙：召回 + 粗筛 + 逐个体检
python scripts/bili.py deep --config job.json -o result.json

# 只看候选池（快，不抓弹幕）
python scripts/bili.py find --topic "数据结构" --mode course

# 体检指定视频
python scripts/bili.py probe --bvid BV1Rs411c7HG BV1Uv411j7fr

# 纯搜索 / 纯详情
python scripts/bili.py search --keyword "线性代数"
python scripts/bili.py detail --bvid BV1Rs411c7HG
```

`job.json`：

```json
{
  "topic": "pwn",
  "mode": "course",
  "deep_n": 8,
  "extra_keywords": ["pwn入门", "二进制漏洞", "CTFpwn", "栈溢出"]
}
```

> 中文参数在 Windows 控制台容易乱码，**优先用 config 文件**而不是 `--topic`。
> `deep_n` 别超过 10——每个候选要发 5 个请求，越多越慢越容易被风控。

### 解锁字幕（可选）

B 站字幕和 AI 摘要在未登录时拿不到（返回 `-101`）。想要逐句核对内容：

1. 浏览器登录 B 站 → F12 → Application → Cookies → 复制 `SESSDATA`
2. `export BILI_SESSDATA=xxxx`
3. 脚本会自动带上并抓 AI 字幕

## 输出长什么样

```markdown
### 【星盟安全】PWN全集
https://www.bilibili.com/video/BV1Uv411j7fr
34 集 · 19.2 小时 · 2021 ｜ 播放 21.5 万 · 收藏 4.6%

讲什么：环境配置 → ELF 格式 → 程序装载 → 栈溢出 → 堆利用 → Linux Kernel UAF
为什么选它：星盟是正经安全团队；官方置顶评论给全套 PPT
适合谁：已懂栈溢出、想系统补原理的人
注意：置顶神评（131 赞）指出"偏移量计算方法没讲清"，偏原理缺实战
```

## 工作原理

```
make_keywords      首轮只用原词，候选 <25 才追加后缀（避免精确查询被带跑偏）
      ↓
search × N         多关键词 × 2 种排序 × 多页 → 去重
      ↓
build_items        硬过滤（时长/播放门槛按模式放开）+ 标题归一化去重
      ↓
score_item         结构 / 口碑 / 相关 / 时效 / 标题 五维加权，按模式改权重
      ↓
diversify          同一 UP 主最多占 2-3 个名额，防批量搬运号占满
      ↓
probe_one          抓大纲、抽查 3 个分P 的弹幕、高赞评论
      ↓
重算分数           用真实分P数 + 大纲覆盖率修正（识破挂羊头）
```

`references/` 里有两份文档：

- `bili-api.md` — wbi 签名算法、接口清单、风控码、**7 个实测踩过的坑**
- `scoring.md` — 权重表、置信度公式、以及每个阈值是怎么校准出来的

## 踩过的坑（都写在 references 里）

| 坑 | 现象 |
|---|---|
| 关键词带空格 | 搜索接口直接返回 **0 条**，编码成 `%20` 或 `+` 都一样 |
| `duration` 格式 | 是 `MM:SS`，**不含分P数**。误判成"分钟:分P数"会让 `8:27` 变成 27 个分P |
| 弹幕是压缩流 | raw deflate，不 `zlib.decompressobj(-15)` 就是一堆乱码 |
| 缺浏览器指纹头 | 只带 UA + Referer 会 `412`，补 `Origin` / `Sec-Fetch-*` 就过 |
| 收藏率小样本失真 | 2 万播放的课能刷出 7% 收藏率，压过 5.8 万收藏的经典课 |
| 标题堆砌营销词 | 「零基础+精通+从浅入深+适合小白」凑一起，通常是搬运号 |

## 已知限制

- **字幕需登录**，未配置 `SESSDATA` 时只能靠弹幕和评论推断内容
- 弹幕只抽查 3 个分P（首/中/末），单P 超长视频无法精确定位难点
- 搜索接口不返回分P数，粗筛阶段用总时长代理"体量"，`deep` 输出才是重算后的准确分
- 直播回放、番剧、付费课程不支持（`view` 接口返回空）
- B 站接口随时可能变，签名逻辑失效时按 `references/bili-api.md` 修
